# ASTRA Mission Pattern Classifier — Model Card

**Model ID:** `ASTRA-MISSION-PATTERN-TREE-1`  
**Algorithm:** scikit-learn `DecisionTreeClassifier`  
**Model artifact:** `data/models/mission-pattern-model.json`  
**Training script:** `scripts/train_mission_pattern_model.py`  
**Generator version:** `astra-synthetic-mission-window-v1`  
**Seed:** `20261115`

## Intended use

The model classifies a short, explicitly simulated or user-entered monitoring window into one of five operational data-pattern labels:

- `STABLE_MONITORING`
- `MULTI_SIGNAL_DRIFT`
- `DATA_QUALITY_REVIEW`
- `WELLBEING_CONTEXT_REVIEW`
- `MIXED_REVIEW`

Its intended purpose is to demonstrate how an offline, explainable classifier can inspect a multi-signal window and surface a review pattern. It does not estimate a person's health, diagnose a condition, predict an event, recommend treatment, or replace a flight surgeon or mission protocol.

## Training data and provenance

The training set contains **15,000 synthetic feature vectors** generated by the versioned Python script in this repository. It contains no real astronaut records, no NASA patient/crew observations, and no data from OSD-575. The five labels are assigned by the simulator's scenario generator; the classifier learns to reproduce those synthetic scenario categories.

The 75/25 stratified split produced 11,250 training rows and 3,750 holdout rows. Random seed: `20261115`. Training environment used Python 3.13.5, NumPy 2.3.5 and scikit-learn 1.8.0.

## Features

| Feature | Meaning |
|---|---|
| `heart_rate_delta_bpm` | Difference between early-window and late-window mean heart rate |
| `spo2_drop_percentage_points` | Early-window mean SpO₂ minus late-window mean SpO₂ |
| `temperature_delta_c` | Late-window minus early-window mean temperature |
| `sleep_delta_hours` | Late-window minus early-window mean sleep duration |
| `missing_rate` | Fraction of expected signal values that are absent |
| `stale_rate` | Fraction of checkpoints with simulated latency over 120 seconds |
| `flatline_rate` | Fraction of adjacent valid signal pairs that are effectively unchanged |
| `wellbeing_flag_count` | Count of illustrative self-report flags in the latest check-in |

All tolerances and simulator distributions are software demonstration settings. They are not NASA standards or clinical thresholds.

| Metric | Result |

| Accuracy | 88.05% |
| Macro F1 | 88.12% |
| Holdout rows | 3,750 |

The confusion matrix and per-class precision/recall/F1 are preserved in the JSON artifact. These numbers describe separation of the synthetic generator only. They are **not** estimates of performance on real crew telemetry.

## Inference and abstention

Inference runs locally in the browser. The app traverses the serialized decision tree and displays the terminal leaf's class share as a **model-support score**, not a calibrated probability or medical risk score.

The system abstains instead of classifying when the input window has fewer than six checkpoints, one or more signals lack enough valid observations, more than 70% of expected values are missing, a feature is invalid/outside the model's supported envelope, the model is unavailable, or terminal class support is below 65%.

The decision path is displayed so users can inspect which feature comparisons led to the class. The pattern output is always kept separate from the deterministic reference-band and personal-reference checks.

## Limitations and risks

- Synthetic data only; no flight telemetry training or external validation.
- The scenario labels are generated by known simulation rules; holdout performance is not evidence of physiological validity.
- Distribution shift, real sensor calibration, human variability, and mission-specific context are not validated.
- The model is unsuitable for clinical, operational flight, emergency, or treatment decisions.
- Synthetic scenario data must never be merged into NASA research observations.
- No personal health values are sent to a remote LLM or inference endpoint; the model executes on-device after the app shell is loaded.

## Reproducibility

Install the development dependencies and run:

```bash
python -m pip install numpy scikit-learn
python scripts/train_mission_pattern_model.py
npm test
```

The training script deterministically regenerates the JSON artifact with the declared seed and parameters. The artifact is included in the repository so the deployed page does not need Python or a network model endpoint.
